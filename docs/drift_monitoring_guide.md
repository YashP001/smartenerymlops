# Data Drift Monitoring Guide

## Overview

The **Data Drift Detection Engine** (`src/monitoring/drift_detector.py`) provides automated monitoring of distribution shifts between historical baseline smart-meter observations and ongoing production observations.

It integrates rigorous statistical hypothesis testing (Kolmogorov-Smirnov two-sample test and Cohen's $d$ effect sizes) with **Evidently AI** (v0.7.23) interactive reporting to deliver both machine-readable JSON summaries and visual HTML drift dashboards.

## Reference vs. Production Data

### Reference Data Baseline
- **Source:** Historical training dataset (`data/train.csv`, $N=18,696$).
- **Rationale:** The model was trained on the distribution characteristics present in `data/train.csv`. Comparing production inputs against this baseline directly measures covariate shift relative to model training conditions.
- **Why Not Validation or Test Splits?**
  - Validation and test splits were held out strictly for model evaluation and hyperparameter tuning.
  - The training split captures the full operational distribution learned by the estimator.
  - The reference dataset is treated as immutable and read-only.

### Production Data
- **Source:** Simulated smart-meter data streams generated by `src/simulation.py` or actual production prediction logs.
- **Scenarios:**
  - `normal`: Routine operational data preserving baseline correlations with subtle Gaussian jitter.
  - `hvac_shift`: Afternoon/evening (12:00–20:00) energy consumption surges representing seasonal heating/cooling covariate shifts.
  - `sensor_drift`: Hardware calibration bias and elevated measurement noise across energy readings.

## Statistical Methodology

To avoid the common pitfall of relying exclusively on statistical $p$-values (which easily become significant in large sample sizes even for trivial differences, or fail to achieve significance in small samples), our drift detection engine applies **dual statistical criteria**:

### 1. Kolmogorov-Smirnov (KS) Two-Sample Test
- **Purpose:** Non-parametric test of the hypothesis that reference and production samples come from the same continuous distribution.
- **Test Statistic ($D$):** Maximum absolute vertical distance between empirical cumulative distribution functions (ECDFs):
  $$D = \sup_x |F_{\text{ref}}(x) - F_{\text{prod}}(x)|$$
- **Thresholds:**
  - P-value threshold ($\alpha$): $0.05$.
  - Distance threshold ($D_{\text{threshold}}$): $0.15$.
  - High sample sizes alone do not trigger drift unless the distribution distance $D \ge 0.15$.

### 2. Standardized Effect Size (Cohen's $d$)
- **Purpose:** Quantifies the magnitude of the mean difference in terms of pooled standard deviations:
  $$d = \frac{\bar{X}_{\text{prod}} - \bar{X}_{\text{ref}}}{s_{\text{pooled}}}, \quad s_{\text{pooled}} = \sqrt{\frac{s_{\text{ref}}^2 + s_{\text{prod}}^2}{2}}$$
- **Threshold:**
  - Effect size threshold ($|d|_{\text{threshold}}$): $0.20$ (standard threshold for non-trivial small-to-medium effect size).
- **Rule:** A feature with $|d| \ge 0.20$ and $p < 0.05$ indicates a meaningful distribution shift.

### 3. Safe Handling of Constant Columns
- If both reference and production features have zero variance (constant):
  - Identical constants: Drift is **not** flagged ($D=0, p=1.0, d=0.0$).
  - Different constants: Drift is **flagged** ($D=1.0, p=0.0$).
- If one distribution is constant and the other has non-zero variance (variance loss or gain):
  - Drift is **flagged** ($D=1.0, p=0.0$).

## Monitored Feature Schema & Drift Taxonomy

### 1. Model Input Features (Covariate Shift)
All six canonical model input features from `src/features.py` are continuously evaluated:
- `energy_current_hour` (kWh)
- `energy_previous_hour` (kWh)
- `energy_two_hours_ago` (kWh)
- `target_hour` ($0\dots23$)
- `target_day_of_week` ($0\dots6$)
- `target_is_weekend` ($0$ or $1$)

**Dataset-Level Drift Decision:**
- **Drift Share:** $\text{share} = \frac{\text{count(drifted input features)}}{\text{total input features (6)}}$.
- **Dataset Drift Detected:** Flagged as `True` if $\text{share} \ge 0.50$ (i.e., at least 3 of 6 model features exhibit drift).

### 2. Target Column (Concept / Outcome Shift)
- Monitored column: `target_next_hour`.
- **Target Drift Separation:** Drift in `target_next_hour` is recorded and flagged independently under `target_drift`. It does **not** artificially inflate the input-feature drift share, preserving a clean separation between **covariate shift** (inputs) and **concept/outcome shift** (targets).

## Evidently AI Integration

The engine utilizes Evidently AI's `Report` and `DataDriftPreset` to generate interactive diagnostic artifacts:
- **HTML Report (`reports/drift/drift_report_<scenario>.html`):**
  - Standalone interactive report featuring distribution curves, quantile comparisons, and drift scorecards for each feature.
- **JSON Summary (`reports/drift/drift_report_<scenario>_summary.json`):**
  - Machine-readable audit file containing timestamps, scenario identifiers, dataset paths, sample counts, feature-level metrics, and dataset-level flags.

## CLI & Python API Usage

### Command Line Interface

Analyze pre-existing simulated datasets or synthesize on-the-fly:

```bash
# Analyze normal operations
.venv\Scripts\python.exe src/monitoring/drift_detector.py --scenario normal

# Analyze HVAC consumption shift
.venv\Scripts\python.exe src/monitoring/drift_detector.py --scenario hvac_shift

# Analyze sensor drift
.venv\Scripts\python.exe src/monitoring/drift_detector.py --scenario sensor_drift

# Run drift analysis across all three scenarios
.venv\Scripts\python.exe src/monitoring/drift_detector.py --scenario all --samples 500 --seed 42

# Compare custom reference and production CSV files
.venv\Scripts\python.exe src/monitoring/drift_detector.py \
  --reference data/train.csv \
  --production data/simulated/simulated_hvac_shift.csv \
  --scenario custom_hvac \
  --output-dir reports/drift
```

### Python API

```python
from src.monitoring.drift_detector import run_drift_analysis

results = run_drift_analysis(
    reference_data="data/train.csv",
    production_data="data/simulated/simulated_hvac_shift.csv",
    scenario="hvac_shift",
    output_dir="reports/drift",
    generate_reports=True,
)

print("Dataset drift detected:", results["dataset_drift_detected"])
print("Drift share:", results["drift_share"])
print("Drifted features:", results["drifted_features"])
if results.get("target_drift"):
    print("Target drift:", results["target_drift"]["target_drift_detected"])
```

## Known Limitations

1. **Univariate Assessment:** The KS test and Cohen's $d$ evaluate marginal feature distributions individually. Complex multivariate interaction shifts that preserve 1D marginals are not detected by univariate tests alone.
2. **Telemetric Scope:** Drift detection monitors active energy consumption ($\text{kWh}$) and calendar indices. Raw electrical signals (voltage, current, power factor) are not part of the model feature schema and are therefore not monitored directly.
3. **Report Storage:** Generated HTML and JSON report files are isolated under `reports/drift/` and intentionally excluded from Git tracking via `.gitignore`.
